# 耳アド(MIMI ADVANCE) 仕様書 — Claude Code 移行用

このドキュメントは、claude.ai上でのプロトタイプ(HTML/JS単一ファイル)で検証・確定した仕様をまとめたものです。Claude Codeでの本実装(React Native想定)の起点として使ってください。プロトタイプのソース自体も一次資料として併用できます。

---

## 1. コアループ概要

1. プレイヤーは複数キャラ(ランナー)を所持し、1体を選んで操作する
2. 選んだキャラは自動でトラックを走り続け、一定間隔でザコ(他ユーザーの育成キャラ、ダミー)を追い抜いてランナーptを獲得する
3. ザコを規定数追い抜くとそのステージのボスが出現し、バトルで撃破すると次のステージへ進む
4. ランナーptでステータスを強化し、ボスを効率よく倒せるようにする
5. ボス撃破やVSレースでVicマネーを獲得し、シューズ強化・新キャラ解放に使う
6. キャラLv.(ステータス合計)が一定値に達すると進化でき、進化で新しいステータスや見た目が解放される

---

## 2. ステージ進行

### ボス到達時間(5ステージごとに階段状に増加)

| ステージ範囲 | 到達時間(秒) | 増分 |
|---|---|---|
| 1〜30 | 15→30 | 5ステージごとに+3秒 |
| 31〜60 | 35→60 | 5ステージごとに+5秒 |
| 61〜100 | 70→140 | 5ステージごとに+10秒 |
| 101〜150 | 155→290 | 5ステージごとに+15秒 |
| 151〜 | 継続 | 同じ調子(+15秒/5ステージ)で延長 |

```js
function timeToBossSec(stage) {
  if (stage <= 30) return 15 + Math.floor((stage - 1) / 5) * 3;
  if (stage <= 60) return 35 + Math.floor((stage - 31) / 5) * 5;
  if (stage <= 100) return 70 + Math.floor((stage - 61) / 5) * 10;
  return 155 + Math.floor((stage - 101) / 5) * 15;
}
```

### ザコ出現・必要数
- ザコは**5秒に1体**の固定ペースで出現する(ガッツで多少短縮、後述)
- そのステージに必要なザコ数 = `round(timeToBossSec(stage) / 5)`(最低1)

### ザコ1体あたりの獲得ランナーpt(ステージ帯で階段状)

| ステージ範囲 | 基礎pt |
|---|---|
| 1〜30 | 10 |
| 31〜60 | 15 |
| 61〜100 | 20 |
| 101〜 | 25 |

実際の獲得pt = `round(基礎pt + テクニック実効値 × 3)`

### 放置報酬(オフライン報酬)
ブラウザ/アプリを閉じている間は何も動かせない(サーバーが無い)ため、**戻ってきたときにまとめて計算する**。
- セーブデータの`lastActiveAt`(最後に状態が更新された時刻)からの経過時間を基準にする。
  状態が更新されるたびに刻み直すので、遊んでいる間は常に直近の時刻になる
- 受け取るタイミングは、**起動直後**と**離れていたタブ/アプリに戻ってきたとき**(AppState `active`)
- 対象は**操作中のキャラだけ**(通常のザコ追い抜きと同じ)
- 計算式(`src/domain/offline.ts`)
  - 対象時間 = `min(経過時間, 8時間)`。超過分は切り捨て、ポップアップで「最大8時間分まで」と知らせる
  - **効率50%**: 追い抜き体数 = `floor(対象時間 × 0.5 ÷ ザコ出現間隔)`(出現間隔はガッツ短縮込み)
  - 獲得pt = 体数 × ザコ1体あたりのpt(テクニック込み。上記)
  - **ボス出現の手前で止める**: 体数は「必要数 − 倒した数」が上限。ボス戦は自動では始まらず、戻ってから自分で挑む
- 1分未満の離席は報酬にしない(タブ切り替えのたびに出ないようにするため)
- 時計が巻き戻った(経過時間が負)場合は報酬なし。時刻の記録が無い古いセーブは、今回を基準にするだけで報酬は出さない
- 報酬があれば「おかえりなさい！」ポップアップで、留守にした時間・追い抜いた体数・稼いだptを表示する

## 3. ステータス(5種)

| ステータス | 効果 | 解放条件 |
|---|---|---|
| **スピード** | 放置中の収入には影響しない。バトル中、相手の消耗ペースにプレッシャーを追加する(`max(0, speed-1) × 1.2/秒`)。自分の消費には影響しない | 最初から解放 |
| **スタミナ** | バトルでの自分の最大スタミナ(`50 + stamina × 20`) | 最初から解放 |
| **ガッツ** | バトルで全力疾走を維持できる時間(`guts × 1600ms`、最大11000msでキャップ)。ステージ到達までのザコ出現間隔をわずかに短縮(`guts-1 × 2%`) | 最初から解放 |
| **テクニック** | ザコ追い抜きの基礎pt加算(上記)。バトル中の障害物によるスタミナ消費を軽減(`max(1, 4 - technique × 0.4)`) | **進化2(evolutionStage≥1)で解放** |
| **アタック(damage)** | バトル中、決まった距離地点で相手に追加ダメージを与える「アタック」が発動(`4 + damage × 2`)。未解放だと発動自体しない | **進化3(evolutionStage≥2)で解放** |

### 未解放ステータスの扱い
- 未解放のステータス(テクニック/アタック)は、キャラLv.・仲間Lv.・バトル効果の**すべてでゼロ**として扱う(基礎値1.0であっても計算に含めない)
- UI上は🔒アイコン+「進化N で解放」の表示、ボタンは押せない(グレーアウト)

### 育成コスト(ランナーpt消費、+0.1刻み)

```js
const STAT_COST_CONFIG = {
  // 5ステータスとも完全に同一。以前はスピード/テクニックだけ割高にしていたが、
  // 同じLv表示なのにコストが桁違いになり(例: Lv30でスピードがスタミナの558倍)、
  // 実機で見ると壊れて見えるという指摘があったため撤廃。ステータス間の強さの差は
  // コストではなく各効果の係数(battle.tsのbossPressurePerSecなど)側で調整する方針にした。
  speed:     { base: 3, growth: 1.02 },
  technique: { base: 3, growth: 1.02 },
  stamina:   { base: 3, growth: 1.02 },
  guts:      { base: 3, growth: 1.02 },
  damage:    { base: 3, growth: 1.02 }
};
// cost = max(2, round(base * growth ^ steps))
// steps = round((現在Lv - 1) * 10)
```

### ステータスLv.上限(進化段階で解放)

| 進化段階 | 上限Lv. |
|---|---|
| 0: どうぶつ | 30 |
| 1: けもの脚 | 60 |
| 2: ヒト型 | 無制限 |

### 継承(仲間Lv.)
- 操作中でない仲間キャラそれぞれの**各ステータス × 10%**を合算したものが「仲間Lv.」
- 未解放ステータスはここでもゼロ扱い
- **総合Lv. = キャラLv. + 仲間Lv.**(キャラLv.はシューズ倍率込みの自キャラステータス合計)

## 4. 進化

- 3段階: **どうぶつ(0) → けもの脚(1) → ヒト型(2)**
- 各キャラは `evolutions: [{requiredCharLv, toName}, {requiredCharLv, toName}]` を持つ
- 条件は**キャラLv.**(自分自身のステータス合計、シューズ倍率込み・仲間の継承は含まない)
  - 進化2: キャラLv. 50 以上
  - 進化3: キャラLv. 100 以上
- 進化すると: 名前が変わる(`toName`)/見た目に脚(段階1〜)・腕(段階2)が追加/対応ステータスが解放/`costumeStage` も自動でその段階に更新
- 進化プレビュー画面: 進化前は実際の見た目、**進化後はシルエット+名前「？？？」**で伏せる(ネタバレ防止)。表示項目は「進化条件」(必要キャラLv.のみ、現在値との比較はしない)と「効果」(解放されるステータス名など)

### 着せ替え
- `costumeStage`(0〜evolutionStage)を自由に切り替えて、過去の進化段階の見た目で表示できる。ステータス・進化状態には影響しない、完全に見た目だけの機能
- 将来、課金限定の見た目枠を追加できるよう、ロック枠のUIも用意済み(現状はダミー)

## 5. バトル(ボス戦・VSレース共通エンジン)

タイムラインベースの決定論的シミュレーション。開始時に全結果を計算してから15秒(`BATTLE_MS = 15000`)かけて再生する(スキップ可、結果は変わらない)。

### コース定義
- `BATTLE_DISTANCE_M = 3000`(m)、`MS_PER_METER = 5`(15000ms/3000m)
- 障害物出現地点(m): `[500, 1000, 1500, 2000, 2500]`(ステージボスごとに差し替え可能な設計、現状はデフォルトのみ)
- アタック発動地点(m): `[750, 1750]`(障害物と重ならないようずらしてある。キャラごとに差し替え可能な設計)

### スタミナ計算式(自分側)
```
meMax = 50 + stamina効実値 × 20
sprintDurationMs = min(11000, round(guts効実値 × 1600))   // 全力疾走の持続時間
sprintDrainPerSec = max(cruiseDrainPerSec, 6 - guts効実値 × 0.44)  // ガッツが上がるほど巡航ペースに近づく
cruiseDrainPerSec = 3      // 全力疾走後のペースダウン
obstacleLoss = max(1, 4 - technique効実値 × 0.4)  // 障害物は必ず回避するが微量減る
```
- `sprintDrainPerSec`のガッツ項は後から追加(バランス見直し)。元々ガッツはスプリント延長
  (=高消費な6/秒の時間が延びる)だけで、上げるほど純粋に損になっていた。障害物ダメージ
  軽減はテクニックの役割と被るため、ガッツ自身が延ばしている「スプリントの消費レート」
  自体を下げる形にした(延ばした分、効率も上がる。巡航ペースが下限)。

### スタミナ計算式(相手側=ボス)
```
bossMax = 60 + (ステージ-1) × 10
speedPressure = max(0, speed効実値-1) × 1.2
bossDrainPerSec = 5 + (ステージ-1) × 0.8 + speedPressure
bossPressurePerSec = (ステージ-1) × 0.4   // 自分側のmeDrainRateに加算される
```
- `bossPressurePerSec`は後から追加(バランス見直し)。元々ボスは`attackUnlocked = false`・
  自分への圧力0固定で、自分に一切ダメージを与えられなかった。`bossMax`/`bossDrainPerSec`は
  比率がほぼ一定なため「ボスはどのステージでもだいたい12〜12.5秒で自滅する」だけで、
  自分側の消費はステータスのみで決まりステージに依存せず、一定ラインを超えると
  以降どのステージでも難易度が変わらなくなっていた。ステージに比例した圧力を追加し、
  育成を続ける意味を保っている。ステージ1では0(初回のボス戦の手触りは変えていない)。
- 係数は導入時0.09だったが、育成コストを5ステータス完全共通にした際、スタミナだけに
  全振りした場合の伸びがあまりに強く(stage250でも無敗)、他ステータスを育てる意味が
  薄れることがシミュレーションで判明したため0.4に強化した。この係数の下では、
  スタミナ一点特化(他Lv1)はstage130前後で通用しなくなり、5ステータス均等育成の
  バランス型はstage160前後まで通用する(いずれもLv30時点、evolutionStage2)。
  スピードのpressureToOpponentPerSec係数(1.2)やスタミナのmaxStamina係数(20/Lv)は
  据え置き — 「自分の耐久を直接伸ばすスタミナ」と「相手を早く倒すスピード/アタック」は
  役割が違うぶん単純な数値の一致は目指さず、ボス側の圧力を強めることで
  一点特化のやりすぎに歯止めをかける方向にした。

### アタック(旧称「必殺技」、この名称は使わない)
- `skillBonus = attackUnlocked ? (4 + damage効実値 × 2) : 0`
- ヒット時、瞬間的にゲージが変わらないよう**0.35秒かけてイーズアウトで滑らかに減少**させる(`smoothedDrop`)

### 演出まわりの仕様
- 全力疾走中は頭上バブル「⚡全力疾走」+自分のスタミナゲージが光る演出(テキスト表示はしない)
- 障害物は「必ず回避」(ジャンプ)。ボスも自キャラの位置に届く前に自分の位置でジャンプする(位置ズレを考慮した2段階タイミング)
- ジャンプは着地まで約1秒、頂点(アニメーション40%地点)が実際の到達タイミングに合うよう先出しで開始
- 勝ちが見えてくると、**ボスは右から下がってきて、自キャラも左から前に出て**、お互いに歩み寄る。
  詰め寄り具合は「ボス自身の残スタミナ比率」で決まり(3乗のイーズイン。半分以上残っている間はほぼ動かず、
  尽きる直前に一気に寄る)、スタミナ0で二人が**中間地点(トラック幅の49%)で完全に重なる**。
  自分が劣勢な時だけ、二人とも定位置(自キャラ20%・ボス78%)へ戻る。
  以前は自キャラが定位置(20%)から動かず、ボスだけが長い距離を詰めてくる動きで違和感があったため変更
  (計算は`src/ui/components/track/trackLayout.ts`)
- 自キャラも動くため、障害物のジャンプのタイミングは「障害物が自キャラの位置に届く時刻での、自キャラの位置」から求める
- 勝利: 自キャラが(前に出ている今の位置から)右へ加速して退場(「抜いた！」トーストは削除済み)→「ステージN クリア！」バナー→黒フェードで通常表示に復帰
- 敗北: 相手が右へ退場(トースト「逃げられた...」)→通常表示に復帰(ボスは再戦時に元位置へ)
- 演出中はスタミナゲージ類を隠さず表示したまま維持し、通常表示に戻る瞬間にまとめて切り替える(段階的に消えるとチグハグに見えるため)

### ボス撃破報酬
```
gained（ランナーpt） = 40 + クリアしたステージ数 × 8
vicGained（Vicマネー） = max(2, round(クリアしたステージ数 × 0.4))
```

## 6. VSレース

- **ステージ100到達**(所持キャラの誰か1体)で解放。1日5回まで(日付が変わるとリセット)
- 使用ステータスは「所持キャラの中でキャラLv.(総合パワー)が最も高いキャラ」の生ステータス(継承なし)
- 対戦相手はダミー生成: 自分の最高キャラLv.の±15%の範囲でランダムな総合Lv.を持つ5名。ステータスは総合Lv.を5等分した仮想ステータス
- バトルは上記共通エンジンをそのまま使用。相手側のスタミナ計算式も自分側と同型(相手の速度も自分にプレッシャーを与える、対称設計)
- 勝利報酬: `vicGained = max(10, round(相手の総合Lv. × 0.6))`
- 開始演出: 黒フェード→「VSレース スタート」2秒→バトル。終了演出: 「WIN」/「LOSE」2秒→黒フェード→通常表示

## 7. シューズ

- ステージ・進化に関係なく**Vicマネーのみ**で解放可能(所持キャラ単位で個別管理)
- 解放コスト: **1000 Vicマネー**(固定)
- 解放後は強化可能。コスト式: `shoeCostFor(level)`(base 15, growth 1.03、+0.1刻み。プロトタイプのコードを直接参照)
- 効果: 全ステータスに `1 + シューズLv. × 0.02` の倍率(キャラLv.計算にも反映される)
- 未解放時のUIは🔒アイコンで他のロック中ステータスと統一

## 8. キャラ・新キャラ解放

- **初期所持は「ミミ」1体のみ**
- 2体目以降はVicマネーで解放するロック枠として提示(1度に1枠だけ表示、解放すると次の枠が出る)

```js
const NEW_CHARACTERS = [
  { id: 'c2', name: 'スズ', unlockCost: 50,  evolutions: [{requiredCharLv:50, toName:'スズ・獣脚'}, {requiredCharLv:100, toName:'スズ・ノクス'}] },
  { id: 'c3', name: 'コン', unlockCost: 150, evolutions: [{requiredCharLv:50, toName:'コン・獣脚'}, {requiredCharLv:100, toName:'コン・ヴァル'}] }
];
```
※3体目以降(4体目〜)は現状未定義。思想シート側にも記載がなく、暫定でコンの150Vicを採用している。要調整。

- 解放確認画面: タイトル「新キャラを解放」→「〜を解放しますか？」→所持Vicマネー/消費Vicマネーを枠で表示→「キャラを解放するとランナーとして使用できます。」→解放ボタン(残高不足ならグレーアウトして押せない)
- 解放後は「〇〇 が解放されました！」のポップアップ(トーストではない)

## 9. 通貨・経済まとめ

| 通貨 | 入手方法 | 用途 |
|---|---|---|
| **ランナーpt** | ザコ追い抜き(放置中の自動収入は廃止済み。追い抜いた時だけ入る) | 5ステータスの育成 |
| **Vicマネー** | ボス撃破(少額)、VSレース勝利(まとまった額) | シューズ解放・強化、新キャラ解放 |

- 自動収入(pt/秒)は撤廃済み。「追い抜くことでのみポイントが入る」設計に統一されている

## 10. UI構成の要点(実装時の参考)

- **ヘッダー**: タイトル、ユーザー名ボタン(👤、タップで変更・8文字以内・NGワードチェック、エラーはインライン表示でトースト不使用)、ヘルプボタン(❓、用語集ポップアップ)
- **ランナー行**: 現在の操作キャラ名 + 「📖 一覧・進化」ボタン(同じ行に収める)
- **ステージ行**: ステージ数 / 総追い抜き数
- **演出(トラック)**: 走行アニメーション、遠景/地面の2レイヤースクロール(地面の方が速い)、ボス/ザコ/障害物の出現、頭上ステータスバブル
- **ボスパネル(常設・レイアウトシフトしない)**: 「追い抜き X/Y」ラベル + ゲージ(横幅の約73%)+ 小さめのボスバトルボタン(横幅の約27%、ゲージが溜まるまで非活性)を同じ行に。バトル中はこのパネルの中身がスタミナゲージ表示に切り替わる
- **トレーニングカード**: タイトル行に「ランナーpt」「Vicマネー」を箱型(wallet-chip)で表示。5+1(シューズ)のステータスカードを3列×2行(名前・Lv.表示 + 下段に強化ボタン、ボタンは大きめ・数字が見やすいこと)。カード色はステータムごとに固定(青=スピード、橙=スタミナ、紫=ガッツ、緑=テクニック、赤=アタック、金=シューズ)。ロック中はボタンごとグレーアウトで統一。「キャラLv. + 仲間Lv. = 総合Lv.」を同じ箱型デザインの計算式で表示
- **VSレースカード**: 解放前は条件文言のみ、解放後は残り回数+「対戦相手を選ぶ」ボタン
- **キャラ一覧**: 2列グリッド(横スクロール防止)。ロック中の新キャラ枠も同じグリッドに表示
- **キャラ詳細**: アバター、ステージ・キャラLv.・進化段階、ステータス一覧(上限も表示)、ランナー交代ボタン、進化ボタン、着せ替えボタン
- **ポップアップ vs トースト**: 進化・シューズ解放・新キャラ解放の完了は**ポップアップ**(モーダル、OKで閉じる)。残高不足は**無反応**(トーストなし)。それ以外の一時的な通知(追い抜き成功、ボス出現、バトル中のアタック発動、勝敗など)はトースト
- **セーブ**: localStorage自動保存に加えて、「セーブコード」(base64エンコードしたJSON)による書き出し・読み込み機能あり(環境をまたいだ引き継ぎ用)

## 12. 素材仕様

現状(プロトタイプ)はキャラ・ボス・ザコとも色分けされた図形のプレースホルダーで、
「色を変えるだけ」で使い回している。本番ではキャラごと・進化段階ごとに完全に別絵にする。
以下のサイズは実装済みのコードから実測した、実際にその大きさで画面に出ている値。

### キャラ本体(自キャラ)・ボス 共通(【決定】正方形キャンバスに統一)

- キャンバスは正方形1024×1024pxに統一する(ボスの表示枠が正方形なのに合わせた。
  600×800の縦長案は採用しない)
- 表示サイズはランナー40×56px・ボス56×56pxだが、どちらも同じ正方形の絵を
  ボックスに収める形に寄せる(ランナー側の表示ボックスも、実素材を入れる際に
  正方形寄りに広げる予定。これはコード側の1行の調整で済む)
- ポーズ: 本番は走り3枚+ジャンプ3枚+アタック3枚 = 9枚/進化段階、3段階で27枚/キャラ。
  ただし最初はAIで下絵を試作する段階なので、各キャラ/ボスにつき1枚(立ち・走り中間ポーズ)
  だけ用意し、雰囲気を見てから本番のポーズ差分に進む
- 形式: PNG(背景透過)、同一アクション内の複数枚は同一キャンバスサイズ・同一基準位置
- キャラごとに完全に別絵(現在のプロトタイプの「色替えで済ませる」仕組みは本番では使わない)
- 現状は常時ボビング(0.32秒周期で上下)+ジャンプ時に頭上へオフセットが乗るだけの単一形状。
  実素材が入ったら、走り/ジャンプ/アタックの各ポーズを対応する再生タイミングで差し替える想定
- ボスは3〜5種類を使い回す前提(11章)。正方形統一によりキャラと同じキャンバスで作れる
- 一覧・進化モーダルのキャラアイコン(56/64/80px、下記)も正方形なので、ランナー用の
  絵をそのまま流用できる(専用に別絵を用意する必要がなくなった)

### ザコ

- 表示サイズ: 28×40px
- 優先度低。当面プレースホルダーのままでよい

### 障害物

- 表示サイズ: 12×16px(現状は赤い角丸長方形のみ)
- 素材化するかは未定。優先度はザコと同程度でよさそう

### 背景(遠景・地面)

- 実装済みの仕組み: 横幅200%のレイヤーに同一パターンを2つ並べ、-50%だけスクロールして
  シームレスループさせる方式(実装済みで、絵を差し替えるだけで使える)
- 遠景レイヤー: 高さ24px、上から18%の位置、不透明度0.4。ループ周期10秒
- 地面レイヤー: 高さ4px、下から10%の位置(このラインに全キャラの足元が揃う基準)。
  ループ周期0.15秒(遠景よりかなり速い)
- 本番用に絵を作る場合、横長のシームレスタイル画像として上記の高さ・ループの仕組みに収める
  (1パターン分の実横幅は画面幅に依存するため、固定pxではなくコンテナ幅基準の相対サイズで作る前提)

### キャラアイコン(一覧・進化・着せ替えの各モーダル)

- 使用サイズ: 56px / 64px / 80pxの3種類(いずれも正方形)
- 現状は「耳が2本立った丸」の簡易図形。ロック中枠は同サイズの円アウトラインのみ
- 進化プレビューの「未確定な次の姿」は同形状の黒塗りシルエットで表現
  (実素材が来たら、シルエット版の絵も別途必要になる可能性がある)

### UIアイコン(現状は絵文字で代用)

| 用途 | 現状の絵文字 | 使用箇所 | 目安サイズ |
|---|---|---|---|
| プレイヤー/ユーザー名 | 👤 | ヘッダーのユーザー名ボタン | インライン(13px相当) |
| セーブ | 💾 | ヘッダー円形ボタン | 36×36の枠内 |
| ヘルプ | ❓ | ヘッダー円形ボタン、用語集モーダルタイトル | 36×36の枠内 / 16px |
| デバッグ | 🐞 | ヘッダー円形ボタン、デバッグモーダルタイトル(開発用) | 36×36の枠内 / 16px |
| キャラ一覧 | 📖 | 「一覧・進化」ボタン | インライン(12px相当) |
| ランキング | 🏆 | ランキングリンク、モーダルタイトル | インライン(12px)/ 16px |
| ロック中 | 🔒 | キャラ一覧の未解放枠・ステータスのロック中表示・着せ替えのダミー枠など5箇所 | 最大19px(ステータスカード内)〜インライン |
| 着せ替え | 👗 | 着せ替えボタン | インライン |
| 全力疾走 | ⚡ | バトル中の自キャラ名の横 | インライン |

🔒が一番使い回されている(5箇所)ので優先して置き換える価値が高い。いずれも小さい
インライン表示なので、色付きの簡易SVG/PNGを1〜2サイズ(例: 24×24を基準に表示先で縮小)
用意すれば足りる。デバッグアイコンは本番では非表示にする想定のため素材化は不要。
